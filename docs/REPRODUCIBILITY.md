# Reproduction guide

Run commands from the repository root with a Python 3.11-3.13 environment satisfying `requirements.txt`.

## 1. Main and supplementary generating settings

| Component | Settings |
|---|---:|
| Main S1-S3, n=20,30,50 | 9 |
| Lower-response Supplement S1-S3, n=30 | 3 |
| Time-nonhomogeneity S1-S3, n=20,30,50, late-PD odds 1.5 and 2 | 18 |
| Additional stress configurations | 4 |
| Assessment-count sensitivity | 18 |
| Total distinct generating settings | 52 |

The first 34 settings are generated by `main/simulate.py`. Mixture weights 0.25 and 0.75 are evaluated on the same generated trials.

```bash
python main/simulate.py --suite all --include-stress --weight-sensitivity --reps 20 --workers 2 --cache .cache/main --out results/smoke_main
python main/simulate.py --suite all --include-stress --weight-sensitivity --reps 10000 --workers 8 --cache .cache/main --out results/main
```

The lower-response Supplement settings used by the default program are the settings reported in the Supplementary Material. The generated transition matrices and true response probabilities are exported with each run.

## 2. Assessment-count distribution sensitivity

Short and Long assessment-count distributions are crossed with Main Scenarios 1-3 and n=20,30,50. The primary distribution is already represented by the Main settings and is not generated again by the default sensitivity run.

```bash
python followup/simulate.py --profiles short long --sizes 20 30 50 --scenarios 1 2 3 --reps 20 --workers 2 --cache .cache/followup --out results/smoke_followup
python followup/simulate.py --profiles short long --sizes 20 30 50 --scenarios 1 2 3 --reps 10000 --workers 8 --cache .cache/followup --out results/followup
```

The null threshold is the exact mechanism-A ORR under the corresponding assessment-count distribution, so mechanism A remains at the null boundary.

## 3. Precision-prior sensitivity

This analysis changes the Gamma rate for the hierarchy precision from 1 to 0.5 or 2 while retaining shape 2. It reuses the same 10,000 saved response counts, selected partitions, and efficacy thresholds from the 9 Main and 3 lower-response settings.

```bash
python prior/reanalyze.py --input results/main --inspect
python prior/reanalyze.py --input results/main --smoke --workers 2 --cache .cache/prior --out results/smoke_prior
python prior/reanalyze.py --input results/main --workers 6 --cache .cache/prior --out results/prior
```

The source directory must contain the complete raw trial files. A summary spreadsheet alone is insufficient.

## 4. Transition-matrix precision and stability diagnostic

The reviewer-directed diagnostic evaluates the transition estimator in the nine homogeneous Main settings only. The estimator is identical to the manuscript implementation: observed row counts are normalized when the row has support; an empty row is replaced by `(0.25,0.25,0.25,0.25)`.

Regenerate the Main trajectories needed for the diagnostic:

```bash
python transition_precision/evaluate.py --plan-only
python transition_precision/evaluate.py --smoke --workers 2 --out results/smoke_transition_precision
python transition_precision/evaluate.py --reps 10000 --workers 8 --out results/transition_precision
python transition_precision/report.py --results results/transition_precision
```

Alternatively, use the exact saved Main trial counts from the completed Main analysis:

```bash
python transition_precision/evaluate.py --input results/main --inspect
python transition_precision/evaluate.py --input results/main --reps 10000 --workers 8 --out results/transition_precision_saved
python transition_precision/report.py --results results/transition_precision_saved
```

The primary error calculation includes empty-row replacement. Conditional nonempty-row summaries are reported separately. The diagnostic reports all 16 transition probabilities even though a four-state stochastic matrix has 12 free parameters, because row-specific estimation accuracy and support are the quantities of interest. See `transition_precision/METHODS.md`.

## 5. Outputs and restart

Main and follow-up analyses write manifests, raw per-trial arrays, selected partitions, posterior summaries, and aggregate reports. Prior sensitivity writes posterior-replay results and source integrity checks. The transition diagnostic writes transition-count checkpoints, cell/row error summaries, support-stratified diagnostics, an MSE decomposition, and an Excel report.

To resume an interrupted production command, repeat the same scientific arguments and append `--resume`. Worker count may change where supported. Do not change code, numerical-library versions, seeds, input files, or scientific settings within a partially completed output directory.

Use distinct directories for smoke checks and production. Do not run two processes that write to the same output directory or cache. On macOS, `caffeinate -i` can be placed before long-running Python commands to prevent idle sleep.

## 6. Archival record

For a reproducible manuscript archive, retain the final aggregate CSV files, manifests, execution metadata, source revision, and numerical-library versions. Raw simulation checkpoints may be archived when storage permits, but they are not required to understand the source code or regenerate simulations from the recorded seeds and settings.
